## Why the order matters

The production database is shared by **build 2 on testers' phones** and by build 3.

- `20261010120000_view_mode` makes the database refuse every create, edit and delete for an
  account without access. Build 2 knows nothing of access: from the moment it runs, **every tester
  not on the beta list gets a failed save in build 2**, with no paywall to explain it.
- **But App Review runs build 3 against prod before approval** — it registers or signs in,
  hits the paywall and buys with its own sandbox account. Without the migrations there is no
  `account_access` for the webhook to write, no `paywall_shown_at`, no `has_access()`: a broken
  app and a rejection under Guideline 2.1. (Found 2026-10-11; the first draft had the migrations
  on launch day.)
- So the database goes out **before submitting** (section 4a) with a launch row and **every
  current tester on the beta list for the time being** — build 2 keeps saving for everyone.
  On launch day the date is set to the real one and the testers who were not picked come off
  the list (section 5). Owner's choice, 2026-10-11.
- Everything else (RevenueCat, secrets, functions, the build itself) can be done earlier.
